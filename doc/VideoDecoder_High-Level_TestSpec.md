## Introduction

This document provides an overview of High Level Test Specification requirements for the Video Decoder module. It outlines the scope of testing, objectives, testing levels and approaches, specific test requirements, and expected deliverables.

- `HAL` Interface Header [Interface Header](https://github.com/rdkcentral/rdk-halif-aidl/tree/v0.6/videodecoder/current/com/rdk/hal/videodecoder)
- `HAL` specification documentation in this link - [Video Decoder HAL Specification info](https://wiki.rdkcentral.com/display/RDKHAL/Video+Decoder)

## Module Description

The Video Decoder HAL service provides the interfaces for compressed video to be passed to the vendor layer for decoding.It may be passed secure buffers if it indicates support for secure audio processing.

The output of a video decoder can take 2 routes; non-tunnelled it comes back to the `RDK` media pipeline as a video frame buffer and metadata or tunnelled through the vendor layer.

The choice of whether video is tunnelled or non-tunnelled has no impact on the operational mode of the audio decoder.  It is possible to have tunnelled video and non-tunnelled audio.

The video decoder operational mode can be chosen by the client once opened.

The `RDK` middleware GStreamer pipeline contains an `RDK` Video Decoder element designed specifically to work with the Video Decoder HAL interface.

### Test Stream specifications

L3 test media are local data files for the test suite to inject directly into the HAL.

They are read by the test suite, written into linear buffers and passed into the video decoder.

```bash

<CODEC>_<PRO>_<RES>_<DR>_<COL>_<FR>_<PIX>_<BITRate>_<description>.es (elementary stream file)
e.g.
H265_MAIN10_3840x2160_DR_HLG_DR_BT2020_25p_PIXEL_FORMAT_YCBCR420_18000.es

```

#### Elementary stream files

- Single I-frame or IDR frame
- Single GOPs (closed)
- Multiple GOPs (open)
- Multiple GOPs (open and closed)
